# 梁文峰：Codex 内置宠物

将现有鲸鱼娘的角色形象迁入 Codex 桌面应用的本地自定义宠物系统。名称沿用“梁文峰”，角色说明保留“陪小鲸子一起工作”。

## 能融合的部分

- 角色外观与透明动画。
- 内置的工作中、等待输入、完成与失败等任务状态。
- 应用自带的宠物显示、大小、拖动、快速聊天与进度入口。

内置宠物是动画资源包。它没有开放运行本项目 WPF 菜单、新闻服务、待办面板或自定义气泡的接口。这些功能及称呼偏好、收藏和计时记录由本项目的后台功能服务继续保存；安装角色资源不会修改或删除它们。角色说明中的称呼也不会自动成为所有 Codex 对话的称呼规则。

配套的 `whale-companion` 技能将现有工具带入宠物快速聊天。新聊天中可输入 `$whale-companion`，再说“帮我看看待办”“专注 25 分钟”或“看看新闻”。技能会读取最新称呼，检查操作是否真正完成。普通写入在服务离线时返回未执行；明确说“打开桌宠待办面板”等请求时，可以恢复隐藏功能服务并打开指定面板，不会弹出独立角色。排队或启动请求成功不等于提醒已经保存，需查看实际结果。

## 安装与选择

项目内的角色已经通过应用自带 `hatch-pet` 流程生成并检查，可运行以下入口安装资源：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File packages\native-pet\install.ps1
```

安装器将 `pet.json` 与 `spritesheet.webp` 放在 Codex 的 `pets/liangwenfeng-whale/` 目录中，并核对已验证图像的哈希；已有角色会先备份。配套技能首次安装时写入 `skills/whale-companion/`，遇到已修改技能时保留用户版本。它不迁移或重置桌宠用户数据，也不替你选择角色。

打开 **设置 → 宠物 → 刷新**，选择 **梁文峰**。内置宠物的可见性仍由应用自身管理。

### 更新后能选角色，但形象不变

2026-10-22 在本机 Codex 26.1016.8120 中确认：本地鲸鱼娘文件完整，当前应用仍支持 v2 的 1536 × 2288 图集；应用已经把该角色迁入共用的云端宠物库，但实际活动角色仍是默认宠物。重新安装同一份图片不能修复选择绑定。

遇到这一现象时，先区分素材加载与角色选择：核对本地文件，再通过 Pets 管理能力查询现有角色的稳定 ID 和活动状态。只有确认是同一个已迁移角色时，重新选择其现有 ID，并核对应用同步后的 `selected-avatar-id` 与实际显示。不要删除原角色、创建重名副本，或把临时图片链接保存成角色身份；本机这次在重新绑定后已由用户确认恢复显示。

本次没有更换图片或重建角色，原有桌宠数据不受影响。不要将网页宠物的尺寸要求直接套用于桌面的 v2 图集。

## 与原桌宠共存

v2.4 在“设置与称呼”中增加了显示方式：

1. 在 Codex 的宠物设置中选择内置的“梁文峰”。
2. 打开本项目“设置与称呼”，选择 **使用应用内置宠物（保留原功能面板）** 并保存。
3. 保留 **打开 Codex 自动唤醒**。之后打开 Codex 时会恢复功能服务，独立角色保持隐藏；若此前为了避免重复角色关闭过此选项，可重新开启。
4. 用托盘或明确的聊天请求打开待办、专注、新闻、设置或检查面板。需要原互动时，切回 **独立桌宠**。

显示方式只是选择本项目角色的呈现方式，不能替 Codex 控制内置宠物是否显示。原来的隐藏与退出也保留：普通隐藏不会强行显示角色；退出会停止功能服务，待办、称呼、收藏和计时记录仍保留。不要删除原桌宠的数据目录。

内置模式下，已保存的提醒、专注结束和已开启的新闻分享通过 Windows 托盘通知交付，不唤出独立角色。通知仍遵循离开、专注、待处理提示与新闻夜间限制，并受 Windows 的通知设置影响。普通独立桌宠的主动隐藏沿用延迟展示规则；切换显示方式不会清空待交付提醒。

服务离线时，也可从已安装目录手动打开设置并保持角色隐藏：

```powershell
powershell -NoProfile -STA -WindowStyle Hidden -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA\CodexWhalePet\whale-pet-start.ps1" -SupportOnly -OpenPanel settings
```

自定义安装请改用实际安装目录。若面板没有响应，可运行项目的 `tools/diagnose-pet.ps1`，或打开托盘中的“检查与修复建议”；检查不会自动启动或删除任何数据。
