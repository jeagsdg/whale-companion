## 后台工作减少的方式

- `state.json` 根据修改时间和长度复用解析结果；JSON 单次读取设有 1 MiB 上限。
- 角色隐藏时停止动画、粒子和游标碰撞检测，主循环降到 500 毫秒，必要计时、回执和心跳仍工作。
- HTTP 桥空闲时等待新连接唤醒，最长 250 毫秒后继续处理必要维护。
- 继续复用合并在桥中的 Codex 增量监听和有界图片缓存；新闻刷新是短期工作进程，诊断只在明确请求时执行。

这些变化降低重复读取与无展示价值的工作。此记录不提供固定的 CPU／内存节省比例；需在相同设备和使用状态下测量后再作比较。

## 使用与恢复

使用内置角色时，打开本项目的“设置与称呼”，选择 **使用应用内置宠物**，保留“打开 Codex 自动唤醒”。需要功能时明确说“打开桌宠待办面板”“打开桌宠专注面板”或“打开桌宠检查面板”。这些面板请求可以恢复已有后台服务，独立角色保持隐藏。

内置模式以托盘通知交付明确请求的陪伴消息、已保存的提醒、专注结束和已开启的新闻分享；独立桌宠的普通隐藏仍延迟展示。系统通知设置、离开、专注、待处理提示和新闻夜间限制仍生效，不通过重新显示角色来强行交付。

普通读操作读取已保存数据；普通写操作在退出或离线时返回未执行。操作排队、请求启动和实际执行完成分别报告；收到请求不能替代执行回执。恢复后应先查看原数据，避免把已经完成的动作重复提交。

检查服务时，从托盘打开 **检查与修复建议**，或在项目目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\diagnose-pet.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tools\diagnose-pet.ps1 -Format json -OutputPath .\桌宠健康检查.json
```

自定义安装时用 `-PetHome` 指向安装输出中的实际目录。检查不联网、不自动重启、不读取聊天正文或配置密钥，不修改偏好、待办或收藏。若组件缺失，可重新运行安装程序；安装前保留原备份。
