# Codex 桌面伙伴 2.4 架构

## 打开宿主唤醒与退出

`whale-host-watch.ps1` 是静默启动入口，优先启动小型 .NET `whale-host-watch.exe`；PowerShell 循环仅作为缺少组件时的备用和测试路径。每两秒检查一次 Codex 主窗口。Store 版 Codex 的进程名实际是 `ChatGPT.exe`，同时核对 `OpenAI.Codex_*` 包路径和非零主窗口句柄，排除独立 ChatGPT 和 Electron 子进程；不读取窗口标题、聊天、截图或键盘。

纯模型 `whale-host-lifecycle.ps1` 用 PID、创建时间和主窗口出现/消失判断打开。新出现时调用单实例启动器 `-Auto -HostOpen`；独立桌宠模式恢复上次退出并显示一次，内置宠物模式恢复功能服务并保留独立角色隐藏。同一宿主周期的隐藏或退出被尊重；正常健康检查没有显示动作。关闭到托盘后重新打开也算一次打开。异常停止最多三次启动，带 15/30/120 秒退避；持续健康 30 秒后才重置次数。`autoWakeOnHostStart` 可关闭联动。

登录入口仅启动监听，不直接显示 UI。MCP 加载时检查监听心跳并作为备用启动入口，标准输出只用于 MCP 协议。启动器为正在初始化的组件保存 20 秒的 PID/时间记录，防止异步启动期间重复创建。UI 退出后桥和聊天监听结束，宿主监听继续等待下一次打开。该联动不依赖可选 Hooks 的信任状态，不更改原生授权。

专注完成的待展示提醒与完成计数保存在 `companion-data.json`，隐藏或重启不会丢失。保存失败时恢复原状态；展示后确认提醒。显示请求必须显式、45 秒内有效，并晚于用户最新隐藏动作。

主进程路径采用只读的 `QueryFullProcessImageName`，不枚举 Electron 模块。辅助库源代码为 `WhaleHostNative.cs`，由 Windows PowerShell 5.1 的 `tools/build-host-native.ps1` 生成；以程序集字节加载避免路径区域限制与升级时文件锁，缺库时由同份源代码构建。

若旧 DSH 控制文件确认已经退出，Codex 安装器先备份其启动组件，再停止该旧目录的残留桥进程，并增加退出检查。旧手动入口经 `codex-preferred.json` 转到用户选定的新目录，旧自动后台入口立即返回；不更改 DSH 其他插件。`-NoStart` 隔离安装不执行旧目录退休。

桌宠是一个本机 Windows 陪伴界面，由当前 Codex 通过受限的本机工具与它联动。它保存称呼、养成、待办和提醒，读取公开新闻源，并展示 Codex 工作状态。它不运行独立 AI 模型，不要求 API 密钥，也不会因状态更新自动启动 Codex 或创建聊天。

## 事件和动作的流向

```text
本机 Codex 会话日志
  → whale-pet-http.ps1 驱动 whale-codex-core.ps1：增量读取、提取状态元数据
  → whale-host.ps1：校验身份、时间，生成固定的提示文案
  → host-events/*.json
  → whale-pet.ps1：显示表情、气泡或“带我去看”提示

Codex 受限本机工具
  ↔ whale-mcp.mjs：通过标准输入输出连接
  → commands/*.json
  → whale-companion-ui.ps1：校验、执行、保存用户数据
  → command-results/*.json：处理回执

明确请求打开功能面板，且服务离线
  → whale-pet-start.ps1 -SupportOnly -OpenPanel <panel>
  → 恢复功能服务、打开所请求面板，独立角色保持隐藏

可选 Codex 原生事件钩子（用户审阅并信任之后）
  → codex-hook.ps1 → whale-host.ps1 → host-events/*.json

桌宠新闻定时器 / 手动刷新
  → whale-news-worker.ps1：短期隐藏进程，读取所选公开 RSS
  → news.json + news-refresh-status.json
  → 新闻收件箱 / 适时分享一条
  ↔ news-schedule.json：共享刷新与分享计划
```

`whale-companion.ps1` 负责称呼、偏好、待办、提醒和专注的数据规则；`whale-companion-ui.ps1` 负责设置窗口、列表、新闻收件箱与工具命令。`whale-pet-common.ps1` 提供原子 JSON 写入、共享读取、身份哈希和互斥锁名称。

## Codex 状态监听和隐私

监听目录默认为 `%CODEX_HOME%\sessions`；未设置 `CODEX_HOME` 时使用 `%USERPROFILE%\.codex\sessions`。遍历日期目录，按实际修改时间选择最近 24 小时最多 160 个候选文件，再保留最多 6 个合法主会话；子代理身份有界缓存，不重复解析。恢复的旧聊天可能保存在很早的日期目录，发现过程不再根据目录日期提前排除它。默认从文件末尾开始监听，不把此前完成的任务再次通知。`-Replay` 和 `-Once` 是隔离回归测试入口。

v2.3 的 `whale-codex-core.ps1` 由桥接进程驱动，持有原来的 Codex 互斥锁并共享主循环，不额外启动 PowerShell。`whale-codex.ps1` 保留为兼容测试入口。读取缓冲可重用，原始行预筛选跳过与工作状态无关的消息和输出，仍保留完整换行与 UTF-8 边界规则。

读取保留字节偏移与 UTF-8 解码器状态，等待完整换行后才解析记录。中文或 emoji 横跨 256 KiB 读取边界时不会变成替换字符；未写完的 JSON 暂存在内存里。连续工具调用合并限速，避免一轮工作刷出许多气泡。

白名单转换任务开始、完成、中断、失败、工具调用和请求用户输入。传给桌宠的记录只包含宿主、状态、会话标识、姿态、固定提示文案、项目名、时间与通知标识，不保存提示词、对话消息、工具参数、输出或推理文本。会话标识只接受 UUID 或规定的 `thr_` 格式；超过 2 分钟的旧事件、超过 30 秒的未来时间，以及非法时间值会被丢弃。

工作阶段另以闭集 `read/edit/test/review/research/build/art/work` 传递。工具名与最多 16 KiB 的参数样本只在读取端分类，原始内容不写入事件。展示先替换双方称呼，再替换项目占位符，避免把项目名里的“你”等文字误改成用户称呼。工作进行时不插入随机生活表情。

已按本机 Codex CLI `0.145.0` 的会话日志验证。日志适配不是稳定的官方 API；Codex 升级若改变记录格式，需调整 `Convert-PetRolloutEvent` 和发现规则。监听能力仅适用于本机可读取的会话目录，不能据此承诺云端会话状态。

原生钩子是可选补充，登记 `SessionStart`、`UserPromptSubmit`、`PermissionRequest`、`Stop`、`Interrupt` 和 `SessionEnd`。钩子不输出许可裁决、不修改工具输入、不触发下一轮；它只提取同一组元数据。基本日志监听不依赖钩子信任。

`codex-hook.ps1` 显式设置标准输入 UTF-8，避免 Windows PowerShell 5.1 按系统默认编码解码中文项目名。原始输入只在当前进程读取，输出事件仍遵守元数据白名单。

## 17 个受限的本机工具

`whale-mcp.mjs` 是标准输入输出 MCP 服务，由 Codex 加载。配置在 `mcp_servers.whale_companion` 下，使用现有 Node.js 运行时。Codex 的 MCP 配置与本机服务方式见 [官方文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)。

| 工具 | 职责 |
|---|---|
| `pet_status` | 读取偏好、养成、当前状态和会话标识 |
| `pet_say` | 请求显示一条最多 240 字的陪伴消息 |
| `pet_set_names` | 设置桌宠名和固定用户称呼，各最多 24 字 |
| `pet_list_todos` | 读取本机待办 |
| `pet_add_todo` | 添加最多 120 字的待办 |
| `pet_set_todo_done` | 用已有待办 ID 标记完成或重新打开 |
| `pet_focus_status` | 读取专注剩余时间、暂停状态与完成次数，离线时也可读取 |
| `pet_focus` | 开始 5～180 分钟专注 |
| `pet_pause_focus` | 暂停专注并持久化剩余秒数 |
| `pet_resume_focus` | 从保存的剩余秒数继续专注 |
| `pet_cancel_focus` | 取消本次专注 |
| `pet_list_reminders` | 读取一次提醒与交付状态 |
| `pet_remind` | 设置 1～1440 分钟后的一次提醒，最多 120 字 |
| `pet_news` | 读取带来源、原文链接与时间的新闻缓存 |
| `pet_refresh_news` | 请求后台刷新所选公开来源 |
| `pet_open_panel` | 明确打开 `tasks/focus/settings/news/diagnostics` 面板 |
| `pet_command_result` | 查询已提交命令的处理回执 |

工具只提供这些动作，不提供任意命令执行能力。它校验参数、文本长度、目录内命令标识和队列上限；用户主动退出、功能服务心跳过期或命令队列已满时，普通写入请求直接返回错误。`pet_open_panel` 是显式打开界面的例外：离线时只调用已安装启动器的 `-SupportOnly -OpenPanel`，恢复功能服务并打开指定面板，不显示独立角色、不启动 Codex。启动请求返回 `requested`，不作为已打开或操作成功的证明；在线服务的面板请求同样通过队列回执确认。

写入先进入本机队列，由 UI 校验 5 分钟有效期并处理。回执保存完成或失败状态；重试不重复执行已完成的待办或提醒。陪伴消息在隐藏、专注、离开或待处理提示时暂缓，过期后不补刷屏。读取工具直接返回本机数据，新闻查询不会暗中刷新联网。

## 授权和钩子信任

Codex 模式中，桌宠的审批和提问牌只提供“带我去看”。`Submit-PetDecision` 仅允许 `host: dsh` 的真实 DSH 审批；Codex 不使用桌宠允许/拒绝结果，原生审批权限保持完整。

`tools/install-codex-integration.ps1` 只登记本项目的 MCP 配置；`-WithHooks` 才登记原生事件钩子，保留已有其他钩子与通知。配置更新前做独立备份，使用原子替换写回。

用户必须在 Codex `/hooks` 审阅并信任对应钩子定义后，钩子才会执行；新定义或定义变更都需要审阅。安装器不修改信任记录、不添加绕过信任的启动参数，也不改工具授权策略。这是 Codex 的原生机制，见 [官方 Hooks 文档](https://learn.chatgpt.com/docs/hooks)。

## 启动、隐藏、退出和恢复

所有桌宠启动经过 `whale-pet-start.ps1`。启动器按安装目录持有互斥锁，UI 和 Codex 监听器也各自持有目录互斥锁；HTTP 桥按监听端口持有互斥锁。重复手动启动不会留下第二只桌宠。

子进程以隐藏窗口启动，避免可见控制台或资源管理器弹出。已有健康 UI 保持当前显示状态；状态监听器只读事件、写文件，从不把 Codex 拉到前台。双击宠物或点击“带我去看”才属于明确的手动宿主跳转。

主动隐藏保存 `hidden.json`，UI 继续运行并保留托盘；自动状态和提醒不会删掉这个标记。明确召回才清除隐藏标记。WPF 使用应用消息循环，隐藏窗口不会导致 UI 退出；提示更新不调用窗口激活。

主动退出先写 `control.json` 的 `stopped: true`，再关闭 UI；本地桥和 Codex 状态监听器读取这个标记后结束。使用 `-Auto` 的开机入口尊重停止标记；手动启动会清除停止状态、补齐缺失组件，`-Show` 明确召回。恢复桌宠无需创建新聊天，也不启动 Codex 本体。MCP 的普通动作不会恢复退出的桌宠；明确的 `pet_open_panel` 请求可恢复隐藏功能服务。

`displayMode` 为 `desktop` 或 `native`。`native` 复用现有 WPF 进程和托盘承载功能面板，把独立宠物窗口隐藏；不额外创建第二套待办、计时或新闻存储。`-SupportOnly` 写入带 `supportOnly` 的隐藏记录，避免单独打开面板后又因宿主健康检查弹出角色。原生皮肤仅由 Codex 的本地自定义宠物机制加载，动画包不执行本项目脚本，也不能证明 Codex 中的宠物已选中或可见。

内置模式使用托盘通知交付明确请求的陪伴消息、已保存提醒、专注结束与合适时机的新闻分享。提醒仍受离开、专注与待处理提示抑制；新闻另遵守独立开关、夜间、频率与配额规则。通知调用失败时保留提醒供后续交付；Windows 是否实际显示通知由系统设置控制。普通独立角色的主动隐藏仍延迟展示，不自动切换为托盘提醒。

隐藏时停止角色动画、粒子更新和游标碰撞检测，主计时器降到 500 毫秒，必要的队列、计时和心跳继续处理。`state.json` 按修改时间和长度缓存解析结果；共享 JSON 读取有 1 MiB 上限。HTTP 桥空闲时使用可被新连接唤醒的 250 毫秒 socket 等待，避免紧密轮询。这些是减少后台工作的机制，实际内存和 CPU 需要在目标运行场景测量。

## 实用功能与数据保存

默认名字是“鲸鱼娘”，用户称呼是“你”。设置页限制两个称呼各最多 24 字；系统台词使用 `{pet}`、`{user}` 占位符，也兼容旧称呼。待办和提醒正文最多 120 字，未完成待办最多 50 条，未触发提醒最多 20 条。

待办、提醒和专注截止时间持久化到 `companion-data.json`。专注默认 25 分钟，可设 5～180 分钟；取消不计完成，正常完成只累计一次。到期提醒遇到隐藏、离开、专注或待处理提示会延后并合并，避免返回桌面时逐条轰炸。每 50 分钟的休息提醒默认关闭。

`quiet: true` 是默认的安静陪伴：减少主动气泡、随机演出和自动走动，保留手动互动和需要处理的提示。新闻有独立的分享开关和频率设置，不依赖安静模式开关。

| 数据 | 用途 |
|---|---|
| `pet-preferences.json` | 宿主、称呼、显示方式、陪伴模式、专注时长、新闻偏好 |
| `companion-data.json` | 待办、提醒、专注截止时间与暂停剩余秒数 |
| `pet-stats.json` | 等级、签到、成就、战绩、专注完成次数 |
| `pet-memory.json` / `position.json` | 项目记忆与桌面位置 |
| `lines.json` | 用户台词 |
| `news.json` / `news-schedule.json` | 新闻缓存、已分享项和定时安排 |
| `news-library.json` | 已读身份及收藏的完整新闻，独立于缓存过期 |
| `news-refresh-status.json` | 最近刷新状态、固定故障码、时间和耗时，可重建 |
| `runtime-version.json` | 运行组件的安装版本标记 |
| `host-events/` / `commands/` / `command-results/` | 状态事件、动作队列与回执 |

记录以 UTF-8 保存，通过相邻临时文件原子替换；读取兼容同时写入与替换。UI 为旧偏好补缺失字段，修复越界配置，保留正常自定义值。历史养成、记忆和位置迁移规则继续保留。

## 新闻与表情

新闻分类为科技、AI、国内、国际、游戏，默认关注科技和 AI。11 个公开来源包括 IT之家、OpenAI 官方、MIT News、Microsoft Research、Google Research、NASA、中新网国内与国际、联合国中文新闻、Xbox Wire 和 PlayStation 官方博客。RSS/Atom 解析限制大小、检查来源域名、清理文本，不执行远端 HTML 或脚本；文章保留来源、语言、发布时间、抓取时间与原文链接。

默认随机分享间隔 60～180 分钟，每天最多 3 条；设置允许更长间隔或关闭分享。夜间 23:00～08:00、独立桌宠主动隐藏、离开、专注和待处理提示时暂停主动分享；内置模式改用托盘渠道。刷新在短期隐藏工作进程中进行，不阻塞 WPF。断网保留缓存，手动收件箱可以查看缓存；主动分享只选最近 24 小时的有效新闻，记录已分享身份并去重，不把旧缓存包装成新消息。

来源的抓取话题与每条文章的分类分开处理：只选 AI 或游戏时仍抓取 IT之家，但仅把对应文章纳入本次结果。合并时按来源建立一次索引，为每个来源最多预留十条，再按时间补齐，总量不超过一百条；避免高频科技来源驱逐低频官方公告。

实际预留量使用 `min(10, floor(100 / 活跃来源数))`，来源超过十个时仍保证总量上限与公平保留。下载在最多三个短期 runspace 中并发完成，单源请求八秒超时，整轮等待预算四十秒；取消后的资源回收仍受当前请求超时约束。所有 runspace 在完成、失败和超时路径释放，不留下常驻池。每源记录检查时间、最近成功、最新文章、数量与状态；空订阅、长期未更新、缺少日期和网络故障分开展示。来源健康展开区只更新同一文本控件，保留展开状态与限定高度滚动。

刷新锁记录 PID 和进程启动时间，崩溃或 PID 重用后可以立即识别；仍兼容四分钟有效期的旧锁。工作进程写入 `queued/running/completed/failed` 状态，来源错误只记录固定分类与耗时，HTTP 错误响应也会关闭连接。面板区分全部失败、部分失败与更新未完成。手动和自动刷新共用结果时间：成功约一小时后再检查，部分失败十五分钟、离线或失败五分钟；无法启动工作进程时一分钟后可再试。新闻计划另有目录级互斥，避免多个调用方同时消耗分享配额。

桌宠 PNG 从 59 张补齐至 92 张，`sticker-catalog.json` 记录每张图片的相对路径、中文文案、英文文案、分类和情绪标签。六类收藏夹为情绪、工作、生活、天气、节日、互动。新增图片由原有 WebP 无损转出，沿用原 MIT 资源。

v2.3 新增 12 张由内置 imagegen 单独生成的透明 PNG，提示词见 `STICKER-V3-PROMPTS.md`。清单版本 2 使用 `recommended` 控制常用入口和随机池、`bindings` 重定向工作状态；旧图仍可浏览。显示位图按宽 320 解码、冻结，最多缓存 8 张，文件流加载后关闭。剪贴板保留原始 PNG 字节，另附文件列表与纯白底 Bitmap 供丢弃透明度的旧应用使用；不复制窗口、字幕或预览底色。

独立导出包含 4 套 PNG 和 1 套 GIF，共 460 个文件：512 像素无字/字幕版，240 像素无字/字幕版，以及真正的两帧循环轻跳动画。动画先生成两张固定尺寸的帧再合并，避免对合并后的长图缩放导致动画退化为一帧。生成器不依赖 DSH 程序的硬编码目录；可加载本地或 Codex 随带 `sharp`。`tools/verify-stickers.mjs` 用真实解码器核对尺寸、透明通道、帧数和帧差异。

## 安装、升级和旧 DSH 兼容

`tools/install-codex.ps1` 默认安装到 `%LOCALAPPDATA%\CodexWhalePet`。程序以追加复制更新，不镜像删除；保留已知用户文件及未知用户数据，资源目录和表情清单可随升级更新。安装器只停止目标目录所属的 UI、桥和 Codex 监听器，隔离安装不会停止其他目录的桌宠。

首次迁移从 `%USERPROFILE%\.dsh\whale-pet` 读取用户文件白名单，目标已有数据优先，不复制旧审批、心跳、隐藏、显示和退出控制文件；偏好合并 `host: codex`。迁移标记保证旧目录后续变化不会再次覆盖新数据。备份在 `<PetHome>.backups/日期-标识`，与运行目录独立，首次迁移还完整备份旧目录。

安装器默认更新并启动桌宠，开机快捷方式启动静默宿主监听。`-NoStart` 禁止进程操作，`-NoStartup` 不写开机项。2.1 部署启用宿主监听开机入口，实现打开 Codex 后自动唤醒。Codex 接入仍由 `tools/install-codex-integration.ps1` 单独登记，两个步骤各自备份数据和配置。

升级时，登录任务及其独立监视器先于 UI launcher 启动，避免监视器变成 Codex 子进程而丢失独立生命周期。使用 `-NoStartup` 时，仅恢复已经登记且目录、派生名称、唯一执行动作和当前用户身份全部匹配的既有任务，不注册或修改任务；`-NoStart` 连该恢复动作也跳过。任务未建立运行状态与新鲜心跳时，不放行界面启动来掩盖失败。

DSH 兼容安装器 `tools/install.ps1` 独立保留，运行偏好必须为 `host: dsh`。其客户端与宿主仍通过本机 v2 HTTP 桥绑定 `clientId + id + sessionId + requestId`，排队审批，按所属客户端领取并确认裁决。桥只监听回环地址，校验来源、方法、令牌和正文大小；普通状态不撤掉审批，OPTIONS 不读取或删除裁决，正文按字节数读取 UTF-8。该能力只属于旧 DSH 模式，不能用于给 Codex 自动授权。

## 只读诊断

`whale-diagnostics.ps1` 同时供“检查与修复建议”窗口和 `tools/diagnose-pet.ps1` 使用。检查只在明确请求时运行，不新增常驻定时器、不联网、不自动重启，也不修改用户数据。报告包括组件心跳、安装版本、必要文件、显示模式、新闻刷新状态以及有界抽查的命令与回执；大目录标注抽样限制。

JSON 单文件读取上限 1 MiB，每个队列目录最多枚举 256 项，至多读取 64 个排队动作和 64 个回执；日志只扫描末尾有限字节并输出错误数量，不返回日志正文。报告不读取聊天正文、配置密钥或待办内容。命令行支持 `-PetHome`、`-Format text|json` 与 `-OutputPath`，诊断结果可以复制或导出。
